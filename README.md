# 饮片炮制记录台

一条记录是一整包炮制文书，里面是工序数组，不是拆成多列指标的普通表单。清炒温度和时长不在范围内就不能放行。

开炒按能耗日额度卡控：炮制员在「能耗额度」页设定本日可用能耗点，每笔成功写入按 `温度 × 时长 ÷ 10` 取整扣点（多工序求和）。超额拒写并提示本日已用与额度；额度改完下一次提交起生效；每日零点额度与已用清零，清零动作写入额度流水。质检员可查阅今日已用与额度流水，不可改额度、不可开炒。

## 接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | /api/energy/quota | 今日已用 / 额度 / 剩余（两角色均可查） |
| PUT | /api/energy/quota | 设定本日额度（仅炮制员），写 set 流水 |
| GET | /api/energy/ledger | 额度流水：set / consume / reset |
| POST | /api/batches | 开炒写入，先扣能耗点，超额返回 409 |

## 验收

1. processor 登录后，甘草为放行，黄芩为未放行（温度过低）。
2. 再写一条温度 200 的清炒，结论仍是未放行。
3. checker 看不到写入按钮，顶栏「能耗额度」页可查阅今日已用与额度流水，但无额度设置表单；直接调 PUT /api/energy/quota 返回 403。
4. 能耗卡控：额度设 100 → 写 100℃×10 分钟（耗 100 点）成功且额度耗尽 → 同档第二笔被 409 拒写并提示已用/额度 → 额度改 200 后再写成功。
5. 每日零点额度与已用清零，额度流水出现一条 reset 记录。
